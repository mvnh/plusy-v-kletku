7.1 Переполнение

Помимо особенностей вещественных чисел, есть особенности целых из-за ограничений архитектуры. Главная — переполнение: результат арифметической операции превышает максимальное значение, представимое в типе.

  • Беззнаковые (unsigned): циклический перенос, 255 + 1 = 0 для unsigned char. Это определённое поведение, арифметика по модулю 2ⁿ.
  • Знаковые (signed): поведение не определено в C/C++ (UB). Но на уровне процессора обычно происходит циклический переход: 127 + 1 = −128 для signed char (8 бит, дополнительный код).

Тонкость для зануд: s++ для signed char формально считается в int (там переполнения нет: 128 спокойно влезает), а потом 128 преобразуется обратно в signed char. С C++20 такое сужающее преобразование определено и даёт −128. Настоящее UB — когда переполняется сам int/long long, как в примере ниже.

Покрути «циферблат»: тип int8, жми +1 на 127 и −1 на −128. Числа ходят по кругу:

… 125 → 126 → 127 → −128 → −127 → … → −1 → 0 → 1 → …

Если бы знаковое переполнение всегда давало «круг», зачем называть его UB? Потому что компилятор имеет право считать, что UB никогда не происходит, и оптимизировать код исходя из этого. Самый наглядный пример:

(А g++ вообще может выдать 1 даже без оптимизаций.)

Правило: не допускай знакового переполнения в принципе. Проверяй до операции: if (a > INT_MAX - b) { /* не влезет */ }, или считай в более широком типе: static_cast<long long>(a) + b.

  • Ariane 5, 1996. Через 37 секунд после старта ракета самоуничтожилась: 64-битное вещественное значение горизонтальной скорости преобразовали в 16-битное знаковое целое, оно не влезло, и инерциальная система «легла». Код был перенесён с Ariane 4, у которой скорости были меньше. Это один из самых дорогих багов в истории.
  • Проблема 2038 года. Время в UNIX — число секунд с 1 января 1970. В 32-битном знаковом time_t оно переполнится 19 января 2038 года в 03:14:07 UTC. Поэтому современные системы перешли на 64-битный time_t, а старые встраиваемые железки до сих пор ждут своего «2038».
Что из этого — определённое поведение?
  1. int x = INT_MAX; x++;
  2. long long y = LLONG_MIN; y--;
  3. unsigned z = 0; z--;
  4. int w = 5 / 0;
Только беззнаковое переполнение определено: z станет 4294967295 (для 32-битного unsigned). Остальное — UB.
