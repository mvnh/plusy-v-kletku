14.1 Ссылка — второе имя объекта

Ссылка — альтернативное имя объекта в памяти. Её можно воспринимать как указатель, который не нужно разыменовывать.

Если указатель — бумажка с номером дома, то ссылка — второе имя самого дома. «Дом Петровых» и «дом 15» — это один и тот же дом.

Ссылка связывается не с переменной как таковой, а с областью памяти:

Ссылка (T&) не является объектом и не имеет собственного размера: стандарт не требует, чтобы она занимала память. sizeof, применённый к ссылке, возвращает размер типа, на который она ссылается: sizeof(int&) == sizeof(int). В отличие от указателя, ссылка не хранит адрес явно, она лишь даёт другое имя существующему объекту.

Но если ссылку нельзя «соптимизировать» (например, она передаётся в функцию), то во время выполнения она обычно реализована как указатель и занимает столько же: sizeof(void*), обычно 8 байт на 64-битной системе.

Правила работы со ссылками

  • Связываются раз и навсегда. Нельзя поменять область памяти, на которую ссылается ссылка.
  • Отсюда: ссылки по определению константны. int& const rx = x; — бессмысленно (ссылка и так неизменяема).
  • Связываются только с областью памяти (lvalue): int& x = 0; — CE.
  • Нельзя создать ссылку на void.
  • Нельзя создать ссылку на ссылку.
  • Ссылка обязана быть инициализирована при создании: int& rx; — CE.
  • Нельзя создавать массивы ссылок: int& array[2]{x, y}; — CE.

r = b — это присваивание a = 7, ссылка не перепривязывается. Потом меняется только b. Итого 7 7 3.

Передача по константной ссылке

Обычная ссылка позволяет функции изменить аргумент, а это не всегда нужно. Копировать тяжёлый объект тоже плохо. Решение — константная ссылка: без копии и без права менять.

Копирование примитивных типов очень дешёвое, поэтому их лучше передавать по значению. Передача по ссылке имеет смысл для тяжёлых объектов (структур, классов, std::string).

Сигнатура вроде void process(const std::string& payload) — самая частая строчка в C++-коде любой компании. Забытый & в горячей функции, куда приходят мегабайтные JSON-ы, означает копию мегабайта на каждый вызов. Такие баги находят профайлером, и они реально роняют производительность сервисов.

Функция должна принять большую структуру Order (килобайты данных) и только прочитать её. Лучшая сигнатура?
  1. void check(Order o)
  2. void check(Order& o)
  3. void check(const Order& o)
  4. void check(Order* o)
Без копии и с гарантией «не изменю». Вариант B тоже без копии, но позволяет случайно испортить данные и не принимает константные объекты и временные значения.
