В C++ можно определить поведение операций для классов, структур и перечислений. Это перегрузка операций. Наравне с перегрузкой функций и шаблонами — проявление статического полиморфизма.

a + b для пользовательского типа — это просто вызов функции с необычным именем: operator+(a, b) или a.operator+(b). Всё остальное — следствия.

26.3 Правила и особенности

  1. Нельзя переопределять операции для примитивных типов: хотя бы один аргумент должен быть пользовательского типа.
  2. Нельзя вводить новые операции (например, ** для степени).
  3. Нельзя менять арность и приоритет операций.
  4. Нельзя переопределять ::, ., ?:, .*.
  5. =, (), [], -> перегружаются только как методы класса.
  6. && и || при перегрузке теряют «короткое замыкание» (до C++17 теряли и строгий порядок вычисления, как и запятая).

Если операция — метод, левый операнд всегда объект этого класса, и неявные преобразования для левого операнда невозможны. Если они нужны — делай внешнюю функцию.

Если бы operator+ был методом, 5 + z не скомпилировался бы: у числа 5 нет методов.

Какие перегрузки запрещены?
  1. Vec operator*(const Vec&, double);
  2. int operator+(int, int);
  3. bool operator==(const Vec&, const Vec&);
  4. Vec operator^^(const Vec&, const Vec&);
  5. Vec& Vec::operator=(const Vec&);
B — оба операнда примитивные. D — операции ^^ в языке нет. Остальное законно.

26.4 Префиксный инкремент и декремент

Для базовых типов ++x и --x меняют значение на ±1 и возвращают ссылку на ту же переменную. Стоит повторять это поведение (компилятор не проверит).

26.5 Постфиксный инкремент и декремент

x++ и x-- возвращают копию старого значения. Чтобы отличить постфиксную версию от префиксной, (внезапно!) добавляют фиктивный аргумент типа int. Он не используется, только подсказывает компилятору.

Вот и объяснение совета из главы 9 «пиши ++i»: постфиксная версия обязана сделать копию старого значения. Для int компилятор это соптимизирует, а для тяжёлого класса копия реальная.

26.8 Операция присваивания

  • Классическое = присваивает значение правого аргумента левому и возвращает ссылку на левый операнд (*this).
  • Реализация не обязана следовать соглашению, но мир станет лучше, если следовать.
  • Одна из четырёх операций, которые бывают только методами.
  • Часть «правила трёх».

Если не реализовать свой оператор, компилятор создаст его сам: присвоит каждое поле и вернёт ссылку. Код выше избыточен — без него было бы то же самое. Явно попросить сгенерированный: Complex& operator=(const Complex& other) = default;

Проблема самоприсваивания

Сначала удаляется a.buffer_, а потом копируются элементы из other.buffer_ — который уже удалён, ведь other — ссылка на тот же a. Чтение освобождённой памяти — UB. Лечится проверкой в начале:

Составные операции присваивания

+=, -=, *= и т.д. меняют левый операнд и обычно возвращают ссылку на него. В отличие от =, ограничений нет: это обычные бинарные операции. Но, как правило, их делают методами.

Частый приём: реализовать += методом, а + выразить через него внешней функцией: Complex operator+(Complex a, const Complex& b) { a += b; return a; }. Логика сложения пишется один раз.

26.9 Сдвиги для ввода/вывода

Так сложилось, что >> и << переопределяют не по прямому назначению, а для ввода из потока и вывода в поток:

  • std::cin — объект класса std::istream (чтение из стандартного ввода);
  • std::cout — объект класса std::ostream (запись в стандартный вывод);
  • есть и другие потоки: std::ifstream/std::ofstream (файлы), std::istringstream/std::ostringstream (строки).

Где-то в <iostream> перегружена >> с левым операндом std::istream и правым int (и другими базовыми типами). Чтобы работала цепочка std::cin >> x >> y; (то есть (std::cin >> x) >> y), операция должна возвращать поток:

friend

Операциям ввода/вывода обычно нужен доступ к приватным полям, поэтому их делают друзьями класса.

Друзья класса — внешние сущности (функции, другие классы или методы других классов), которые имеют доступ к приватной и защищённой части класса.

Друга можно сразу объявить и определить внутри класса. Другом может быть и метод другого класса, и класс целиком:

Дружба не взаимна и не транзитивна: если A объявил B другом, это не значит, что A — друг B, и друзья B не становятся друзьями A. Дружбу «даёт» тот, чьи приватные части открываются.

Ввод/вывод для своего типа

Итоговый шаблон, который пишется почти всегда так:

Почему operator<< для своего класса нельзя сделать методом этого класса (чтобы писать std::cout << z)?
  1. Потому что << можно перегружать только для чисел
  2. Потому что он должен быть const
  3. Потому что у метода левый операнд — объект класса, а здесь слева стоит std::ostream
  4. Можно, просто так не принято
Метод класса Complex означал бы запись z << std::cout. Слева в std::cout << z стоит поток, а дописать метод в чужой класс std::ostream мы не можем. Поэтому — внешняя функция, а для доступа к приватным полям — friend.

Операция сдвига, которая на самом деле печатает текст, — ровно та ситуация, про которую говорят: «перегружай операции так, чтобы они делали очевидное». Комитет стандартизации нарушил это правило в первой же библиотеке, и теперь мы живём с std::cout << (1 << 3), где скобки обязательны.
