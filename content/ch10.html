10.1 Объявление и определение функций

Структурное программирование — парадигма, в основе которой лежит представление программы в виде иерархической структуры блоков (логически объединённых последовательностей инструкций).

Основные принципы:

  • используются операторы последовательности, ветвления и циклы;
  • операторы можно вкладывать друг в друга;
  • повторяющиеся фрагменты объединяются в подпрограммы — функции.

Функция — элемент программы, который связывает последовательность инструкций с идентификатором (именем функции) и списком параметров.

Как и любую сущность, перед использованием функцию нужно объявить, но не обязательно определить.

Объявление (declaration) знакомит компилятор с существованием сущности (функции, переменной, класса), но не даёт полной реализации и не выделяет память.

Определение (definition) даёт полную реализацию функции или выделяет память под переменную. Определение — тоже объявление (но не наоборот).

  • Синтаксис int ownMax(int x, int y); называется объявлением (прототипом) функции.
  • Объявление (возможно, с определением) должно предшествовать использованию.
  • В объявлении можно опускать имена параметров: int ownMax(int, int);

ODR — One Definition Rule

  1. Любая переменная, функция, класс, шаблон или перечисление должны быть определены ровно один раз во всей программе.
  2. Объявлений может быть сколько угодно, определение — одно.
  3. Для inline-функций, inline-переменных (C++17), констант времени компиляции и шаблонов допускается несколько определений, но они должны быть идентичными во всех единицах трансляции. (Если сложно — пока пропусти.)

В реальных проектах объявления живут в заголовочных файлах .h, а определения — в .cpp. Положил определение обычной функции в заголовок, подключил его в двух .cpp — и линковщик выдаёт multiple definition of …. Это ODR в дикой природе. На семинаре 7 ровно такие задачи: «реализуйте решение в трёх файлах».

10.2 Параметры функций

Параметры в объявлении — формальные, значения при вызове — фактические:

  1. Внутри функции создаются новые независимые переменные — формальные параметры.
  2. В них копируются значения фактических аргументов.
  3. Изменения формальных параметров не влияют на исходные переменные.

Копируются только значения, а не сами переменные:

  • для простых типов (int, double, char…) — копируется значение;
  • для объектов — вызывается конструктор копирования;
  • для массивов — копируется указатель на первый элемент (фактически передаётся указатель, а не все элементы);
  • для указателей — копируется адрес, но не данные по адресу.

Параметры по умолчанию

Некоторые параметры могут иметь значение по умолчанию, тогда при вызове их можно опустить. Такие параметры могут идти только в конце списка.

Аргументы сопоставляются с параметрами слева направо по позиции. Если бы было f(int x = 0, int y), то в вызове f(5) пятёрка ушла бы в x, а y остался бы без значения. Пропускать параметры «в середине» синтаксис не умеет: f(, 5) не бывает.

Если значения по умолчанию указаны в объявлении, в определении их не повторяют:

  1. Параметры по умолчанию указываются один раз, обычно при первом объявлении.
  2. Значения по умолчанию задаются только для последних параметров.
  3. После параметра со значением по умолчанию не может идти параметр без него.

10.3 Возвращаемое значение

10.4 Статические локальные переменные

Статическая локальная переменная — переменная, объявленная внутри функции или блока с модификатором static.

  1. Видна только внутри блока (функции), где объявлена.
  2. Инициализируется ровно один раз — при первом попадании выполнения в её объявление. Без инициализатора — нулём. Живёт до конца программы.
  3. В многопоточных программах гарантируется, что инициализацию выполнит ровно один поток.
  1. Инициализация — только при первом вызове.
  2. Последующие вызовы её пропускают.
  3. Значение сохраняется между вызовами.
  4. Несмотря на «глобальное» время жизни, доступна только внутри своей функции.
Что выведет программа?
Статическая s копится между вызовами (1, 2, 3), а обычная a каждый раз создаётся заново: 0 → 1. r / 10 = s, r % 10 = a. Вывод: 1 1 2 1 3 1. Если бы a тоже была static, получилось бы 1 1 2 2 3 3.

«Статический локальный объект» — каноничный способ сделать ленивый синглтон (Meyers singleton): Logger& get() { static Logger inst; return inst; }. Создастся при первом вызове, ровно один раз, потокобезопасно — благодаря тому самому пункту 3.

10.5 Перегрузка функций

В C функции не могут иметь одинаковые имена, даже с разными параметрами. Наследие видно в <cmath>: abs, labs, llabs, fabsf, fabs, fabsl — шесть имён для одного действия.

Перегрузка функций (overloading) — возможность определить несколько функций с одинаковым именем, но разной сигнатурой: имя, количество, порядок и типы параметров. Возвращаемый тип в сигнатуру не входит. Компилятор выбирает функцию по количеству и типам аргументов.

Функции должны отличаться: 1) количеством параметров; 2) типами; 3) последовательностью типов.

Только возвращаемый тип — не основание для перегрузки. Функции с одинаковыми параметрами и разными возвращаемыми типами — ошибка компиляции.

  1. Модификаторы верхнего уровня (const, volatile) при перегрузке не учитываются.
  2. Параметры по умолчанию могут влиять на разрешение перегрузки.
  3. Преобразования типов учитываются при выборе наиболее подходящей функции.

Разрешение перегрузки

Выбор подходящей функции называется разрешением перегрузки. Оно опирается только на имя и типы аргументов:

  1. Собрать все функции-кандидаты с данным именем.
  2. Оставить те, что можно вызвать с данными аргументами.
  3. Выбрать наилучшую:
    • сначала точное совпадение типов;
    • затем расширение (promotion);
    • затем стандартные преобразования;
    • затем пользовательские преобразования.
  4. Если несколько одинаково подходящих — ошибка (неоднозначность).

В конспекте расширением названы int → long → long long и float → double. По стандарту promotion — это только: типы «меньше int» (char, short, bool) → int, и float → double. А int → long, int → double, double → long double, long → int — уже стандартные преобразования, все одного ранга. Это видно на практике: вызов f(5) при f(long) и f(double) неоднозначен. На экзамене формулируй по конспекту, но знай, как работает компилятор.

Все стандартные преобразования считаются равными, ни одно не приоритетнее другого.

При выборе перегрузки const на верхнем уровне игнорируется, то есть f(int) и f(const int) — одна и та же функция!

Почему? Параметр передаётся по значению: функция получает копию, и вызывающему всё равно, константная она внутри или нет. А const int* — это константность того, на что указывают, она «видна снаружи».

Есть void g(long); и void g(double);. Что будет при вызове g('a')?
  1. Вызовется g(long) — ближе к целым
  2. Вызовется g(double)
  3. Ошибка: неоднозначность
char → long и char → double — оба стандартные преобразования (promotion у char только в int, а g(int) нет). Одинаковый ранг → неоднозначность.

Рекурсивный Фибоначчи не только жрёт память, но и работает за Ω(1,5ⁿ): одни и те же значения пересчитываются экспоненциально много раз. Сравни сам:

  • Любой рекурсивный алгоритм можно свести к итеративному.
  • Рекурсия, как правило, лаконичнее, но требует больше ресурсов.
  • Рекурсию стоит использовать, когда итеративная реализация слишком сложна и это окупает потерю производительности.

Стек небольшой: обычно 8 МБ на Linux/macOS и 1 МБ на Windows. Рекурсия глубиной в миллион вызовов (или без базового случая) переполнит стек, и программа упадёт. Отсюда и название сайта Stack Overflow.

Если вывод не устраивает или невозможен, тип указывают явно:

  1. cv-квалификаторы (const, volatile) игнорируются.
  2. Ссылки отбрасываются.
  3. Массивы низводятся до указателей.
  4. Функции низводятся до указателей на функцию.
  5. Типы, соответствующие одному шаблонному T, должны совпадать (после всего выше).
  • Шаблон функции — НЕ функция!
  • Если шаблон ни разу не вызван, код не генерируется.
  • При вызове создаётся только нужная версия.
  • Генерация кода из шаблона называется инстанцированием.

Это полезно в многофайловых программах, чтобы не инстанцировать одну и ту же функцию в разных единицах трансляции.

Компиляция шаблонов идёт в два этапа:

  1. При объявлении проверяется только синтаксис и то, что не зависит от параметра шаблона.
  2. При инстанцировании — полная проверка и генерация машинного кода.

Перегрузка шаблонов

  • Точные соответствия всегда побеждают остальные перегрузки.
  • Если точных соответствий несколько, выигрывает то, где меньше подстановок и приведений.
  • При прочих равных обычная функция предпочтительнее шаблона.

Специализация шаблона

Решение — специализация: реализация шаблона для конкретного набора параметров.

Нетиповые параметры шаблона

Помимо типов параметрами шаблона могут быть: целые числа, указатели, ссылки, std::nullptr_t, числа с плавающей точкой (C++20) и некоторые классы специального вида (C++20).

Вся стандартная библиотека — шаблоны: std::max, std::swap, std::sort, контейнеры. Когда в 2-м модуле дойдёте до std::vector<int>, это будет ровно инстанцирование шаблона класса vector с T = int.

template <class T> T mx(T a, T b); Что будет при mx(3, 2.5)?
  1. Вернёт 3.0, T = double
  2. Ошибка компиляции: T выводится и как int, и как double
  3. Вернёт 3, T = int
Оба аргумента должны дать один и тот же T. Лечится явным mx<double>(3, 2.5).
