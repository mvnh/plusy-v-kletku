12.1 Текстовый сегмент

Текстовый сегмент (text segment, code segment) — область виртуальной памяти процесса, в которую загружается машинный код программы, сгенерированный компилятором из исходного кода на C++ (или другом нативном языке).

Несмотря на название, «текста» в привычном смысле там нет. Термин исторический: в ранних системах машинные инструкции называли «текстом программы», в отличие от «данных».

12.2 Сегменты памяти процесса

При запуске ОС загружает исполняемый файл в виртуальное адресное пространство процесса, которое логически делится на сегменты:

СегментЧто внутриПример из кода
textмашинный код функций (только чтение)тело int add(int a, int b)
dataинициализированные глобальные и статические переменныеint g = 42;
bssнеинициализированные (нулевые) глобальные и статическиеint counter;, static int total;
heap (куча)динамически выделенная памятьnew int[100], malloc
stack (стек)локальные переменные, параметры, адреса возвратаint x = 5; внутри функции

Сопоставь с классами памяти из главы 3: статический класс — это сегменты data и bss, автоматический — стек, динамический — куча.

В каком сегменте окажется static int hits;, объявленная внутри функции без инициализатора?
  1. stack — она же внутри функции
  2. data
  3. bss
  4. text
Статическая локальная переменная живёт всю программу, значит, она в статической памяти. Инициализатора нет, по умолчанию ноль, поэтому bss. Видна она только внутри функции, но хранится не на стеке.

Почему код именно в отдельном сегменте

  1. Сегмент помечается как read-only, чтобы предотвратить случайную или злонамеренную модификацию кода во время выполнения.
  2. Разделение кода и данных — ключевой принцип защиты.
  3. Если программа запущена несколько раз, ОС может использовать один и тот же text-сегмент для всех процессов. Экономия памяти.

Политика «память либо исполняемая, либо записываемая, но не одновременно» (W^X, NX-бит) — одна из главных защит от эксплойтов. Атаки переполнения буфера раньше писали машинный код прямо в стек и прыгали туда. NX-бит запрещает исполнять стек, поэтому атакующим пришлось изобретать ROP — сшивать эксплойт из кусочков уже существующего кода в text-сегменте.

Как посмотреть

Функция

после компиляции превращается в последовательность машинных инструкций в секции .text, которая при запуске загружается в текстовый сегмент. Заглянуть внутрь (на своём компьютере, в терминале):

  • objdump -d program — дизассемблировать код;
  • size program — размеры сегментов text, data, bss.
   text    data     bss     dec     hex filename
   1240     512      16    1768     6e8 my_program

Здесь text = 1240 байт — объём машинного кода.

Попробуй на маке: clang++ main.cpp -o prog && size prog (на macOS формат вывода свой, по сегментам Mach-O: __TEXT, __DATA). А на godbolt.org видно, во что компилируется каждая строчка.
