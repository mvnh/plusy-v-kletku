Сырые указатели (int*, float*…) дают полный ручной контроль над памятью, но легко приводят к ошибкам:

  • утечки памяти (забыли delete);
  • двойное освобождение (delete дважды);
  • висячие указатели;
  • исключения, прерывающие выполнение до delete.

Для автоматического управления временем жизни в C++11 появились умные указатели — классы-обёртки вокруг сырых указателей, реализующие концепцию RAII (Resource Acquisition Is Initialization, подробно в главе 25). Подключаются через <memory>.

15.1 std::unique_ptr

std::unique_ptr<T> — умный указатель, который единолично владеет объектом типа T. Только один unique_ptr в каждый момент может указывать на данный объект. Копировать его запрещено на уровне компиляции, владение можно лишь передать (переместить) другому unique_ptr. Объект удаляется автоматически, когда unique_ptr выходит из области видимости.

  • Нельзя копировать.
  • Можно перемещать (владение передаётся).
  • Автоматически вызывает delete при уничтожении.
  • Значение по умолчанию — нулевой указатель.

Никогда не отдавай один сырой указатель из new двум разным unique_ptr: оба вызовут delete → двойное освобождение и UB.

Всегда используй std::make_unique: так не будет утечек при исключениях и путаницы с двойными выделениями.

15.2 std::shared_ptr

std::shared_ptr<T> — умный указатель с разделяемым владением. Несколько shared_ptr могут указывать на один объект. Объект удаляется, когда уничтожается последний из них (счётчик ссылок становится равным нулю).

  • Можно копировать — счётчик ссылок увеличивается.
  • Можно перемещать.
  • Хранит счётчик ссылок.
  • Объект удаляется, когда счётчик достигает нуля.

Если два объекта держат shared_ptr друг на друга, их счётчики никогда не обнулятся → утечка. Для разрыва таких циклов используют std::weak_ptr.

15.3 std::weak_ptr

std::weak_ptr<T> — наблюдающий (невладеющий) указатель на объект, управляемый shared_ptr. Не увеличивает счётчик ссылок и не продлевает время жизни объекта. Нужен для безопасного наблюдения без циклических зависимостей.

  • Нельзя напрямую разыменовать.
  • Чтобы получить доступ, вызывают lock(): он возвращает shared_ptr (или пустой, если объект уже удалён).
  • Используется для разрыва циклов.
  • По умолчанию используй std::unique_ptr.
  • Переходи к std::shared_ptr, только если действительно нужно разделяемое владение.
  • std::weak_ptr — для разрыва циклов или временного наблюдения.
  • Избегай сырых указателей для владения памятью.

В кодовой базе Chromium и в Google C++ Style Guide правило звучит так: владение выражается через std::unique_ptr, а голый new/delete в ревью — красный флаг. Классический пример weak_ptr — кэш: кэш «наблюдает» за объектами, но не держит их в живых, если они больше никому не нужны.

Что выведет программа?
weak_ptr счётчик не увеличивает: 1. Копия b — 2. После блока — снова 1.
Объект нужен ровно одному владельцу, а потом владение должно перейти функции-обработчику. Что выбрать?
  1. std::shared_ptr и копию в функцию
  2. std::unique_ptr и std::move в функцию
  3. Сырой указатель и delete в обработчике
  4. std::weak_ptr
Единоличное владение с передачей — ровно то, для чего создан unique_ptr. shared_ptr тут лишний: счётчик и разделённое владение никому не нужны.
