2.1 Типы данных

Тип данных — свойство программных сущностей, которое определяет:

  1. множество допустимых значений;
  2. допустимые операции;
  3. низкоуровневое представление — как интерпретировать биты, то есть как «читать» число.

Типов в C++ много, и мы будем создавать свои. Но любой тип состоит из фундаментальных или является производным от них:

КатегорияТипы
Пустойvoid
Целыеint, short, long, long long
С плавающей точкойfloat, double, long double
Символьныеchar, char8_t, char16_t, char32_t
Логическийbool
Нулевой указательstd::nullptr_t

Почему «интерпретация битов» — это часть типа? Потому что один и тот же байт 11111111 — это 255 для unsigned char и −1 для signed char. Память не знает, что в ней лежит. Знает только тип.

2.2 Целый тип данных

Самый используемый тип — целый, поэтому ему больше всего внимания (и не только сейчас).

int

Стандарт гарантирует, что int занимает минимум 16 бит (2 байта).

На практике почти всегда int — 32 бита (4 байта), диапазон [−2 147 483 648; 2 147 483 647], то есть [−2³¹; 2³¹ − 1]. Литералы: 0, 1, -4, 100, 576843.

Почему асимметрично? Из 2³² комбинаций одна уходит на ноль, а остальные делятся поровну на отрицательные и положительные, кроме «лишнего» отрицательного. Разберёмся в главе про дополнительный код.

long

Стандарт: long — минимум 32 бита и не меньше int.

То есть гарантированный диапазон тоже [−2³¹; 2³¹ − 1]. Литералы: 0l, 1L, -4l, 100L, 1123576843l.

Исторически: на старых 16-битных системах int был 16 бит, а long давал 32. Сейчас его поддерживают для обратной совместимости и чтобы гарантированно иметь минимум 32 бита.

На 64-битных Linux и macOS long — 8 байт, на 64-битной Windows — 4. Код, который «работал на маке», может переполниться на Windows. Нужен точный размер — бери int64_t (ниже). Кстати, наш компилятор в браузере собирает под WebAssembly (32-битная платформа), там sizeof(long) == 4.

long long

Стандарт: long long — минимум 64 бита и не меньше long.

Диапазон [−9 223 372 036 854 775 808; 9 223 372 036 854 775 807] = [−2⁶³; 2⁶³ − 1]. Литералы: 0ll, 1LL, -4ll, 100LL.

short

Стандарт: short — минимум 16 бит и не больше int.

Диапазон [−32 768; 32 767] = [−2¹⁵; 2¹⁵ − 1]. Собственных литералов у short нет.

sizeof

Размер типа узнаётся операцией sizeof:

  • sizeof(type) — размер типа в байтах;
  • sizeof(expression) — размер типа выражения;
  • sizeof variable — размер переменной (скобки можно опустить).

sizeof(char) ≤ sizeof(short) ≤ sizeof(int) ≤ sizeof(long) ≤ sizeof(long long)

Операции над целыми

Над целыми (кроме short!) можно выполнять все арифметические операции по правилам:

  • результат имеет тот же тип, что и операнды;
  • при переполнении беззнаковых — арифметика по модулю 2ⁿ, всё законно;
  • в остальных случаях переполнение — Undefined Behaviour (неопределённое поведение, UB);
  • деление на 0 — UB;
  • битовые сдвиги отрицательных чисел тоже могут приводить к UB.

Если операнды разных типов (или short):

  • (signed/unsigned) short приводится к int;
  • менее широкий тип приводится к более широкому;
  • знаковый тип приводится к беззнаковому.

Правило «знаковый приводится к беззнаковому» рождает шедевры. -1 < 1u — это false: −1 превращается в 4 294 967 295. Запусти и посмотри (компилятор, кстати, предупредит).

Какой тип у выражения 5u + 3ll (на обычной платформе, где long long шире unsigned int)?
  1. unsigned int
  2. unsigned long long
  3. int
  4. long long
Сначала «менее широкий к более широкому»: long long (64 бита) может представить все значения unsigned int (32 бита), поэтому результат — long long. Беззнаковость «побеждает» только когда типы одного ранга (или беззнаковый шире).

Размеры «плавают» между системами, и это бесит. С C++11 есть типы ровно того размера, что в имени. Нужен <cstdint>:

Встречаются два варианта имён: стандартные uint8_t … uint64_t из <cstdint> (C++11) / <stdint.h> (C99) и нестандартные u_int8_t … u_int64_t из старых BSD и некоторых библиотек.

Всегда используй стандартные имена uint8_t и т.д. Нестандартные с подчёркиванием могут не поддерживаться и не гарантируют переносимость.

В сетевых протоколах, форматах файлов (PNG, ZIP), драйверах и финтехе используют только фиксированные типы: заголовок пакета обязан весить ровно 20 байт на любой машине. Если в коде банка видишь int64_t amount_kopecks, это неслучайно: деньги хранят в копейках целым числом фиксированной ширины.

Особенности целочисленной арифметики

  • Целочисленное деление: 10 / 3 = 3 — дробная часть отбрасывается (округление к нулю).
  • Остаток: 10 % 3 = 1.
  • Деление на ноль — UB.
  • Переполнение: знаковых — UB, беззнаковых — по модулю.

Знак остатка совпадает со знаком делимого: -10 % 3 == -1, 10 % -3 == 1. Всегда верно (a / b) * b + a % b == a. Отсюда вечный баг «проверка на нечётность»: x % 2 == 1 не сработает для −3 (там −1). Пиши x % 2 != 0.

Что выведет std::cout << -7 / 3 << ' ' << -7 % 3;?
Деление округляет к нулю: −7/3 = −2.33 → −2. Остаток: −7 − (−2·3) = −1.

2.3 Символьные типы

char

char хранит символ. Символ — это 1-байтовое целое число согласно таблице ASCII.

char всегда занимает ровно 1 байт (обычно 8 бит). Стандарт допускает, что байт больше 8 бит (некоторые встраиваемые системы).

Литералы: 'a', '1', '\n', '@'…

ТипОписание
charЗнаковый или беззнаковый — зависит от компилятора и платформы. Всегда 1 байт.
signed charВсегда знаковый, от −128 до 127. Для маленьких целых чисел.
unsigned charВсегда беззнаковый, от 0 до 255. Для байтовых данных.

Какой из вариантов у «просто char» — зависит от реализации (на x86 обычно знаковый, на ARM Linux — беззнаковый).

char8_t, char16_t, char32_t

Широкие символьные типы для кодировок UTF-8, UTF-16 и UTF-32 (подробнее — на cppreference).

Арифметика с символами

Раз символ — это число, с char можно делать всю арифметику:

'E' + ('a' - 'A') == 'e'

При арифметике всё, что «меньше» int, сначала приводится к int (integral promotion).

Что выведет std::cout << 'a' + 1;?
'a' (97) повышается до int, результат 98 — типа int, поэтому печатается число, а не 'b'.

Трюк c - '0' встречается в любом парсере: JSON, CSV, протоколах. А c - 'a' как индекс в массиве из 26 счётчиков — половина задач на строки на LeetCode (анаграммы, частоты букв).

Логические операции:

В C++ есть и слова and, or, not, но это плохой стиль: они пришли из времён, когда на клавиатурах не было нужных символов. Не рекомендуется, а на нашем курсе запрещено.

&& и || — особенные, «ленивые» (short-circuit):

  1. гарантируется, что левая часть вычисляется раньше правой;
  2. если слева true, правая часть || не вычисляется;
  3. если слева false, правая часть && не вычисляется.

Арифметика с bool

bool — разновидность целого типа: true == 1, false == 0.

И обратно: в логическом контексте ненулевое значение — true, ноль — false.

Чем отличаются & и &&?
  1. Ничем, это синонимы
  2. & — побитовое И, вычисляет оба операнда; && — логическое И, ленивое
  3. && работает только с bool, & — только с int
5 & 2 = 0b101 & 0b010 = 0, а 5 && 2 = true. Плюс & всегда считает обе стороны, а && может не считать правую. Это вопрос 1.4 семинара 1.

2.5 Числа с плавающей точкой

Для хранения рациональных чисел:

  • float — одинарная точность, 4 байта, примерно [±10⁻³⁸; ±10³⁸];
  • double — двойная точность, 8 байт, примерно [±10⁻³⁰⁸; ±10³⁰⁸];
  • long double — расширенная, 12 или 16 байт, примерно [±10⁻⁴⁹³²; ±10⁴⁹³²].
  • Работают те же арифметические операции, кроме битовых и %: 0.1 + 0.2 * 5.67 / 0.9.
  • Точность ограничена: 0.1 + 0.2 != 0.3 (почему — в главе 6).
  • Числа с плавающей точкой всегда знаковые.
  • Есть особые значения +inf, -inf, nan.
  • Разные вещественные типы → менее широкий приводится к более широкому: 5.0 + 1.5f — double, 5.0 + 1.5l — long double.
  • Целое + дробное → целое приводится к дробному: 1 + .0f — float.

Обрати внимание: 1. / 0 (вещественное) даёт inf, это нормально по IEEE 754. А 1 / 0 (целочисленное) — UB, программа может упасть.

2.6 Пустой тип: void

void — тип с пустым множеством значений. Главное применение — сказать, что выражение (функция) ничего не возвращает. Подробно познакомимся в главе про функции.
