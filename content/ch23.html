23.0 Что такое конструктор

Конструктор — особый метод класса, который вызывается при создании объекта.

  • Не имеет возвращаемого значения.
  • Его имя совпадает с именем класса.
  • Вызывается неявно при создании объекта.

Виды конструкторов:

  • параметрический;
  • преобразования;
  • по умолчанию;
  • копирования;
  • перемещения (будет позже).

23.1 Параметрический конструктор

Параметрический конструктор — конструктор, который можно вызвать с несколькими аргументами (больше одного).

23.2 Списки инициализации

К моменту выполнения тела конструктора все поля уже должны быть инициализированы. Присваивание в теле — это уже не инициализация. Особенно важно для полей-ссылок и констант: их нельзя «присвоить», их можно только инициализировать.

Нужная конструкция — список инициализации:

Порядок инициализации полей определяется порядком их объявления в классе, а не порядком в списке инициализации. И даже если ты не написал список инициализации, он всё равно есть (неявный).

clang и g++ предупреждают об этом (-Wreorder). Пиши список в том же порядке, что и поля.

23.3 Конструктор преобразования

Конструктор преобразования — конструктор, который может принимать ровно 1 аргумент. Используется для неявных (и явных) преобразований. (C++11 расширил это понятие, но это уже другая история.)

23.4 Конструктор по умолчанию

Конструктор по умолчанию — конструктор, который можно вызвать без аргументов.

Stack other(); — это функция other, которая ничего не принимает и возвращает Stack. Эту ловушку называют «most vexing parse», «самый досадный разбор». Фигурные скобки Stack other{}; её обходят.

Если ты не объявил ни одного конструктора, компилятор создаст свой конструктор по умолчанию: поля-классы инициализирует их конструкторами по умолчанию, а для полей примитивных типов ничего не делает. Если объявил хотя бы один конструктор — неявного конструктора по умолчанию не будет.

Список инициализации выполняется в любом случае. Компилятор может и отказаться генерировать конструктор по умолчанию, если не понимает, как это сделать:

Если в классе уже есть какой-то конструктор, а писать конструктор по умолчанию лень, можно явно попросить компилятор сгенерировать его. Это эквивалентно конструктору с пустым телом:

struct P { P(int v) {} }; Что будет при P p;?
  1. Вызовется сгенерированный конструктор по умолчанию
  2. Вызовется P(int) с v = 0
  3. Ошибка компиляции: раз объявлен свой конструктор, конструктора по умолчанию нет
Объявил хотя бы один конструктор — неявный конструктор по умолчанию не создаётся. Лечится P() = default; или значением по умолчанию у параметра.

23.5 Конструктор копирования

Конструктор копирования создаёт объект копированием другого объекта того же типа. Единственный аргумент — объект того же типа.

Наивная передача по значению обречена:

Почему рекурсия: чтобы передать a по значению в параметр s, нужно сделать копию a… конструктором копирования, который снова принимает по значению… и так до переполнения стека. На практике компилятор такое просто не пропустит.

Аргумент передают по константной ссылке: так конструктор работает и с временными объектами, и не может испортить оригинал.

Если не объявить свой конструктор копирования (и конструктор перемещения), компилятор создаст свой: поля-классы копирует их конструкторами копирования, поля базовых типов — побитово.

Но компилятор откажется, если какие-то поля скопировать нельзя:

= default для копирования

Хотя достаточно просто не писать свой конструктор копирования — компилятор сгенерирует его сам.
