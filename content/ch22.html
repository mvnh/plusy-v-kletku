22.1 Класс

Класс — описание некоторого концепта предметной области в виде набора полей и методов для работы с ними (описание нового типа данных).

Стек — «стопка тарелок»: кладём сверху (Push), снимаем сверху (Pop), смотрим верхнюю (Top). Последним пришёл — первым ушёл (LIFO). Тот самый стек вызовов из главы 10 устроен ровно так.

22.2 Объект

Объект — экземпляр класса.

Класс — чертёж, объект — дом, построенный по чертежу. Домов можно построить сколько угодно, у каждого свои стены (поля), но планировка (методы) одна.

22.3 Модификаторы доступа

  • public — любой внешний код имеет доступ к полям и методам.
  • private — доступ только у методов самого класса (и у друзей класса, глава 26).
  • Модификаторы можно ставить в любом порядке и количестве.
  • Модификатор действует от точки объявления до следующего модификатора (или конца класса).
  • В struct по умолчанию public.

Обрати внимание: сначала выполняется разрешение перегрузки (выбрана h(double) как точное совпадение), и только потом — проверка доступа. Компилятор не станет «обходить» приватную функцию и вызывать h(int) с преобразованием. Будет ошибка.

Какие строки скомпилируются для класса S выше?
  1. s.h(5);
  2. s.h(5.0);
  3. s.y = 3;
  4. s.g();
h(int) и g() — public. h(double) выигрывает перегрузку для 5.0, но она private → CE. y — private.

22.4 Ключевое слово class

  • Для нового типа вместо struct можно писать class.
  • Классы в C++ полностью эквивалентны структурам, кроме двух нюансов:
    1. в классах модификатор по умолчанию — private, в структурах — public;
    2. классы по умолчанию наследуют приватно, структуры — публично (наследование будет позже).
  • Как правило, предпочитают class. Структуры обычно пишут без методов, только с открытыми полями базовых типов (POD-типы).

22.7 Статические методы

  • Принадлежат не объекту, а классу в целом.
  • Вызываются через объект или через имя класса: S::y, S::g().
  • Работают только со статическими полями: иначе непонятно, чьё это поле.

Константных статических методов не существует: const у метода относится к объекту this, а у статического метода его нет.

22.8 Итоговый класс стека

В конспекте в итоговом классе size_t size_; без инициализатора — тогда у нового стека размер будет мусором. Здесь стоит = 0; в главе 23 то же решается конструктором.

22.9 Логическая и физическая константность

  • Объект логически константен, если с точки зрения пользователя его состояние не меняется (нельзя отличить «до» и «после»).
  • Объект физически константен, если не изменился ни один бит его внутреннего представления.

Пример: для отладки объект считает число вызовов метода. Физически он меняется (счётчик), логически — нет (пользователь этого не видит).

mutable
