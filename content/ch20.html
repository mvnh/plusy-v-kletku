20.1 Общее представление

Структура — составной тип данных, который объединяет набор данных (возможно, разных типов) в одном объекте.

struct Array — ответ на боль из главы 16: массив в функции «забывает» свой размер. Положи указатель и размер в одну структуру — и они путешествуют вместе.

20.3 Статические поля

Статическое поле принадлежит не конкретному объекту, а всей структуре: оно общее для всех объектов и хранится в статической памяти. Хороший пример — счётчик созданных объектов.

Статические поля — разновидность глобальных переменных, а для них действует ODR: ровно одно определение на программу. Поэтому определять статические поля внутри структуры нельзя. Исключение — константные целочисленные:

20.4 inline

У inline два назначения:

  1. подсказка компилятору для оптимизации — встраивание функции;
  2. управление видимостью для соблюдения ODR.

В современном C++ второе важнее и гарантировано стандартом.

Изначально inline просил компилятор подставить тело функции в место вызова, чтобы избежать накладных расходов: сохранения регистров, передачи аргументов через стек, перехода по адресу возврата.

Сейчас для GCC, Clang, MSVC это лишь рекомендация: компилятор может её проигнорировать (например, функция слишком большая), а при -O2/-O3 он и сам встраивает что считает нужным, даже без inline.

Практический смысл inline сегодня — ODR. Если определить функцию в заголовке .h, подключённом в несколько .cpp, линковщик выдаст multiple definition: код скомпилируется в каждый объектный файл. inline разрешает несколько идентичных определений в разных единицах трансляции, и линковщик оставит одну копию.

20.5 Размер структуры. Выравнивание

Размер структуры — не просто сумма размеров полей:

Те же поля в виджете: переставь их и посмотри, откуда берутся 24 и 16.

  • Размер структуры не меньше суммы размеров полей и не меньше 1.
  • Поля лежат в памяти строго в порядке объявления.
  • Каждый объект выравнивается по адресу, кратному его выравниванию (для базовых типов обычно равно размеру): &x кратно alignof(x).
  • Самое компактное расположение — по убыванию размера. Но без необходимости такими микрооптимизациями не занимаются.
  • При необходимости структура дополняется байтами в конце (padding), чтобы в массиве структур все элементы были выровнены.

Упаковка через #pragma pack(push, 1) даёт 15 байт, но так делать не стоит: теряется производительность, а на некоторых архитектурах невыровненный доступ вообще падает.

64-битный Linux. struct T { int a; char b; double c; }; Чему равен sizeof(T)?
a: байты 0–3, b: байт 4, padding 5–7, c: 8–15. Итого 16, выравнивание 8 — хвостового padding не нужно.
