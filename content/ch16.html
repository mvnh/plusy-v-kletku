16.0 Что такое массив

Массив — последовательность элементов одного типа, расположенных непрерывно в памяти, с доступом по индексу через общий идентификатор.

Статический массив — упорядоченный набор элементов одного типа в непрерывной области памяти, размер которого известен на этапе компиляции и не может меняться во время выполнения. Хранится на стеке (если объявлен локально) или в сегменте данных (если глобально).

Выражение в квадратных скобках должно быть положительной константой времени компиляции!

  • Массив int array[10] хранит 10 элементов типа int.
  • Доступ — через операцию индексации: array[0], array[2], array[9]. Индексация с нуля.
  • Гарантируется, что элементы идут в памяти подряд, без разрывов: &a[i] - &a[j] == i - j.

Чтобы адрес любого элемента вычислялся одной формулой за O(1): адрес(a[i]) = адрес(a[0]) + i · sizeof(T). Именно поэтому индексация мгновенная, и поэтому работает арифметика указателей. Бонусом непрерывный кусок памяти отлично ложится в кэш процессора.

16.2 Связь массивов и указателей

Имя массива — «голова» массива, адрес начала. Посмотри по шагам:

В большинстве контекстов массив автоматически преобразуется (decays) в указатель на первый элемент:

  • при передаче в функцию: void f(int arr[]) эквивалентно void f(int* arr);
  • в арифметике указателей;
  • при сравнении.

Исключения (decay не происходит): sizeof, операция &, инициализация ссылки на массив.

Поскольку p[2] — это ровно *(p + 2), а сложение коммутативно, работает даже 2[p]:

Но массив ≠ указатель на первый элемент:

Сравнивать массивы через >, <, == бессмысленно: сравниваются указатели на первые элементы.

Разность указателей на элементы одного массива — количество элементов между ними, а не байтов:

Компилятор знает sizeof(int) и сам делит разницу в байтах на размер типа. Это определено стандартом и корректно только для элементов одного массива.

Поэтому в функцию передают ещё и размер: void f(int* arr, int n). Компилятор даже предупредит про sizeof от параметра-массива.

16.3 Правила работы с массивами

  1. Нельзя создавать массивы ссылок и массивы функций, но можно — массивы указателей и указателей на функции.
  2. Нельзя определить массив неизвестного размера, но можно объявить (например, extern).
  3. При сравнении массивов сравниваются адреса первых элементов, а не содержимое. Для разных массивов == всегда false.
  4. Массивы нельзя присваивать друг другу (исключение — строковые литералы при инициализации).
  5. Лайфхак! Если массив — поле структуры или класса, структуры присваивать можно, и массив скопируется как часть объекта.

16.4 Динамические массивы

Динамический массив — массив, размер которого определяется во время выполнения, а память выделяется в куче через new[]. Существует до явного освобождения через delete[] или до конца программы.

new[] возвращает указатель на первый элемент (а не на массив!), поэтому его нельзя использовать везде, где имя статического массива:

Указатель array не хранит размер массива. sizeof(array) вернёт размер указателя, а не количество выделенных байт. Размер надо помнить самому.

Память из new[] освобождается только через delete[]. delete без скобок для массива — UB.

После delete[] указатель становится висячим. Хорошая практика — сразу обнулить: array = nullptr;

Ручной new[]/delete[] в реальном коде почти не встречается: его заменяет std::vector, который сам растёт и сам освобождает память (второй модуль курса). Но vector внутри устроен ровно так: указатель на блок в куче, размер и ёмкость. Так что сейчас ты изучаешь его потроха.

Что из этого — ошибки (CE или UB)?
  1. int* p = new int[5]; delete[] p;
  2. int* p = new int[5]; delete p;
  3. int a[3]{}; int* p = a; std::cout << p[2];
  4. int a[3]{}; std::cout << a[3];
B — delete без скобок для массива: UB. D — выход за границу (индексы 0..2): UB. A и C корректны.
