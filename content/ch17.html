17.1 C-строки

C-строка — массив символов типа char, завершающийся нулевым символом '\0' (его ещё называют терминалом).

Строковые литералы

Записываются в двойных кавычках: "Hello". Особенности:

  1. Это массивы типа const char[N], где N = длина + 1 (с учётом терминала). sizeof("Hello") == 6.
  2. Хранятся в статической области памяти (часто в «таблице строковых литералов»).
  3. При инициализации массива char литералом происходит копирование (особый случай, разрешённый стандартом): char s[] = "abc"; создаёт {'a','b','c','\0'}.
  4. Сравнение через == сравнивает адреса, а не содержимое: Стандарт не гарантирует, что одинаковые литералы лягут по одному адресу.

Строковые литералы имеют тип const char[]. Попытка изменить их (например, char* p = (char*)"abc"; p[0] = 'x';) — неопределённое поведение (часто — падение: литералы лежат в read-only памяти).

Работа с C-строками

Функции из <cstring>:

strcpy, strcat и подобные не проверяют границы буфера — легко получить переполнение и UB. Избегай их в новых программах.

Переполнения буфера на C-строках — источник легендарных уязвимостей. Червь Морриса (1988) атаковал gets() в сервисе fingerd, Heartbleed (2014, OpenSSL) — чтение за границей буфера, через которое утекали приватные ключи серверов. Функцию gets вообще удалили из стандарта C11.

В современном C++ используй std::string или std::string_view.

Что выведет программа?
sizeof считает байты массива с терминалом: 6. strlen считает символы до '\0': 5.

17.2 std::string

std::string — класс стандартной библиотеки (<string>), изменяемая строка с автоматическим управлением памятью.

В отличие от C-строк, std::string может содержать '\0' внутри и не считает его концом: длина хранится отдельно.

Преимущества std::string:

  • автоматическое выделение и освобождение памяти;
  • безопасные операции (проверка границ в методе at());
  • операции +, ==, < и т.д.;
  • метод size() — длина строки.

std::string можно передать в функцию, ждущую const char*, через метод c_str():

Текст из e.what() зависит от стандартной библиотеки: у libstdc++ (g++) и libc++ (clang на macOS) он разный. Подробно исключения разбираются во втором модуле.

  • std::string::npos — статическая константа типа size_t, равная максимальному значению типа. Означает «не найдено».
  • substr, find, replace работают с позициями (индексами), а не с указателями.
  • Все методы спокойно работают с '\0' внутри строки: это не терминал!

if (s.find("x") >= 0) — всегда true: size_t беззнаковый и не бывает меньше нуля. Сравнивай только с std::string::npos.

Производительность конкатенации

Многократное сложение строк в цикле может быть неэффективным: каждый += потенциально вызывает перевыделение памяти и копирование всего содержимого.

Можно заранее зарезервировать память через reserve():

Альтернатива — std::ostringstream из <sstream>, оптимизированный для последовательной записи.

Преобразования

  • std::to_string(42) — число в строку.
  • std::stoi("42") — строка в int. Бросает std::invalid_argument, если числа нет, и std::out_of_range, если оно не влезает в тип.
  • std::stod("3.14") → 3.14 — в double.
  • Аналогично: std::stof, std::stol, std::stoll, std::stoul и др.

17.4 std::string_view

std::string_view хранит указатель и длину, но не владеет данными строки. Это «окошко» на чужие символы.

Когда использовать:

  • для передачи строк в функции без лишнего копирования;
  • когда данные уже существуют (литерал, std::string, C-строка);
  • в read-only алгоритмах.

Если исходная строка уничтожена, string_view повисает, как указатель:

  • По умолчанию храни строки в std::string.
  • Используй std::string_view для параметров функций (read-only).

17.5 Изменяемость строк

std::string — изменяемый строковый тип: можно менять символы, добавлять и удалять подстроки, переприсваивать.

Если объект объявлен как const std::string, он логически неизменяем: любая попытка модификации — ошибка компиляции. Но сам тип std::string по природе изменяемый.

C-строки: когда изменяемы, а когда нет

  • Неизменяемые: строковые литералы вроде "text" лежат в read-only памяти. Даже если старый компилятор разрешит присвоить литерал в char*, запись туда — UB.
  • Изменяемые: массив, инициализированный литералом (char s[] = "text";), — копия данных в изменяемой памяти (обычно на стеке). Его можно безопасно менять.

Тип строкового литерала — const char[N]. Присваивание его в char* было разрешено в C++98/03, но запрещено с C++11. Современные компиляторы дают ошибку или предупреждение.

В современном C++ для изменяемых строк используй std::string. C-строки — только для взаимодействия с legacy-кодом и системными API.

Какой из вариантов корректно проверяет, что в строке s есть подстрока "cat"?
  1. if (s.find("cat"))
  2. if (s.find("cat") >= 0)
  3. if (s.find("cat") != -1) (компилируется, но читается плохо)
  4. if (s.find("cat") != std::string::npos)
A ложно, если «cat» стоит в самом начале (позиция 0). B всегда истинно. C технически работает (−1 превращается в максимальный size_t = npos), но это хак. D — канон.
