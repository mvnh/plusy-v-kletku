# Гайд разработчика

Как устроена платформа «Плюсы в клетку» и как в неё добавлять главы, задачи, вопросы и виджеты.

## Коротко

- Фронтенд — **одна страница без фреймворков и сборщиков**: ванильный JS, CSS-токены и CodeMirror 5 для редактора.
- Бэкенд — `server.py` на стандартной библиотеке Python. Он раздаёт статику, компилирует и запускает C++ и (по желанию) проксирует Claude или OpenAI API.
- Контент лежит в обычных файлах: главы в HTML с небольшой разметкой, задачи и вопросы в JSON. JSON генерируется Python-скриптами, а **ожидаемые ответы считаются запуском эталонного решения**, а не пишутся руками.
- Зависимостей нет: Python 3.8+ и компилятор C++.

## Цикл разработки

```bash
python3 server.py --no-browser &     # сервер раздаёт корень, перезапуск не нужен
# правишь src/parts/*  →
python3 src/build.py                 # пересобрать index.html (+ проверка контента)
# обнови страницу в браузере (кеш отключён заголовком no-store)
```

Главы (`content/*.html`) подгружаются через `fetch`, поэтому их правки видны после обычной перезагрузки страницы, без `build.py`. Проверить разметку всё равно стоит `build.py`.

Скрипты генерации:

```bash
python3 src/gen_tasks.py              # все задачи
python3 src/gen_tasks.py fizzbuzz gcd # только эти id (остальные берутся из текущего tasks.json)
python3 src/gen_seminars.py
python3 src/gen_cards.py
python3 src/gen_theory.py
python3 src/verify.py                 # все главы; или: python3 src/verify.py 13 14
```

Компилятор для скриптов выбирается так: `$CXX`, иначе `clang++`, иначе `g++`. Для `predict.json` лучше брать clang++: ответы на вопросы с UB брались с него. Все генераторы пишут в `data/`, временные файлы кладут в `$TMPDIR/pvk-gen`.

**Перед коммитом:** `build.py` без проблем, `gen_*` без `FAIL` и `MISMATCH`, `verify.py` → `FAILS: 0`.

## Архитектура фронтенда

Глобальные объекты из `parts/*.js` склеиваются в один `<script>` в порядке `core → runner → render → widgets → views → extras → boot`. Модулей и импортов нет, порядок файлов в `build.py` важен.

- **Роутинг** (`App.route` в `views.js`) работает по `location.hash`:

  | hash | экран |
  |---|---|
  | `#home` | главная |
  | `#ch05` | глава (id из манифеста) |
  | `#practice` | список задач |
  | `#task-<id>` | задача |
  | `#seminars`, `#sem3` | «что выведет» (все / семинар 3) |
  | `#cards` | флешкарты |
  | `#exam` | пробный билет |
  | `#sandbox` | песочница |

- **Гидрация главы.** HTML главы вставляется в `<article>`, затем по очереди: `hydrateQuizzes` → `hydrateWidgets` → `hydrateCode`. Порядок важен: внутри квизов и трейсов есть `<script type="text/x-cpp">`, их должны забрать квиз и трейс, а не общий обработчик кода.
- **Прогресс** (`Store` в `core.js`) хранится в `localStorage['pvk-progress-v1']`:
  ```js
  { read: {"05": 1}, quiz: {"05-q3": true}, tasks: {fizzbuzz: {solved, tries, code}},
    pred: {"s2-2-8": true}, cards: {"c05-3": {box, due, ts}}, exams: [{ts, upto, score}], last, updated }
  ```
  Ключ квиза — `<глава>-q<порядковый номер квиза в главе>`. **Если вставить квиз в середину главы, сдвинутся ключи всех следующих**, и у пользователей «съедутся» отметки. Новые квизы лучше добавлять в конец раздела или главы.
- **Хелпер `h(tag, attrs, ...children)`** создаёт элементы: `attrs.html` → innerHTML, `on*` → обработчики, `class`, `style` и прочее → атрибуты.
- **Тема.** Все цвета — CSS-переменные в `style.css` (`:root` светлая, `prefers-color-scheme: dark` и `[data-theme]` тёмная). Литеральных цветов в компонентах нет; новые элементы стилизуй через токены.

## Сервер (`server.py`)

| Метод | Путь | Тело → ответ |
|---|---|---|
| GET | `/api/info` | → `{ok, error, cxx, std, version, os, ai, provider, model}` |
| POST | `/api/compile` | `{src, opt}` → `{ok, log, id}`; `opt`: `-O0`, `-O2`, `-O0 san` |
| POST | `/api/run` | `{id, stdin, timeout}` → `{stdout, stderr, code, ms, timeout?, trap?}` |
| POST | `/api/ai` | `{messages, system?, tools?, max_tokens?}` → ответ в формате Messages API (`{content, stop_reason}` или `{error: {type, message}}`) |

- Компиляция: `<cxx> -std=<лучший из c++23/2b/20/17> -Wall -Wextra`, плюс `-O0`/`-O2`. Режим `san` добавляет `-g -fsanitize=address,undefined`. Бинарники кешируются по sha256 от (компилятор, флаги, исходник) в `$TMPDIR/pvk-cpp/<hash>/`; сборки старше суток удаляются при старте.
- Запуск: свежая временная папка (cwd) на каждый запуск, поэтому программы с `fstream` не мешают друг другу. Таймаут убивает всю группу процессов. Вывод режется на 200 000 символов. Сигналы (`SIGSEGV`, `SIGFPE`…) и коды исключений Windows превращаются в понятное `trap`.
- **Безопасность.** POST принимается только с `Host: 127.0.0.1|localhost` (защита от DNS rebinding) и с заголовком `X-PVK: 1`. Кастомный заголовок нельзя отправить с чужого сайта без CORS-preflight, а на `OPTIONS` сервер отвечает 403. Слушается только `127.0.0.1`. Не ослабляй эти проверки: сервер по сути выполняет произвольный код.
- **ИИ.** Ключ берётся из `ANTHROPIC_API_KEY` или `OPENAI_API_KEY` только на сервере; провайдера выбирает `ai_provider()` (`AI_PROVIDER`, иначе первый с ключом, Anthropic в приоритете). Модель: `ANTHROPIC_MODEL` (по умолчанию `claude-sonnet-5-5`) или `OPENAI_MODEL` (по умолчанию `gpt-4.1`); `OPENAI_BASE_URL` направляет запросы на другой OpenAI-совместимый сервер. Страница всегда говорит на формате Anthropic Messages (`text`/`tool_use`/`tool_result`, `input_schema`): для OpenAI `server.py` переводит запрос в Chat Completions (`openai_messages`, `tools[].function`) и ответ обратно (`openai_to_anthropic`), а ошибки приводит к типам `authentication_error`/`rate_limit_error`/`overloaded_error` (`openai_error`). Поэтому `extras.js` про провайдера ничего не знает.

На фронте `Runner` (`runner.js`) повторяет этот API: `compile(src, opt)`, `exec(comp, stdin, {timeout})`, `run(src, stdin, {opt})`. Результаты компиляции кешируются в памяти страницы.

`LocalAI` (`extras.js`) — обёртка над `/api/ai` с интерфейсом `sample(input, {onText, tools, signal})` и `sample.json(prompt)`. Она сама крутит цикл tool use: инструменты выполняются в браузере. Так тьютор вызывает `run_cpp` и проверяет свои утверждения реальным запуском. Ответы не стримятся: `onText` вызывается после каждого раунда.

## Формат главы

`content/chNN.html` — фрагмент HTML без `<html>`/`<body>`. Каждый раздел оформляется как `<section>` с `<h2>`. Из `<h2>` строится оглавление главы и кнопка «✦ объясни проще».

```html
<section>
<h2><span class="sn">5.1</span> Поразрядные битовые операции</h2>
<p>Обычный текст, <code>код</code>, <b>акценты</b>.</p>
…
</section>
```

Новая глава регистрируется в `content/manifest.json`:

```json
{"id": "27", "n": 27, "group": "oop", "title": "Наследование", "pages": "250–262", "min": 40, "blurb": "Одна строка для карточки на главной"}
```

`group` берётся из `groups`. Задачи и вопросы привязываются к главе по `id` (`"ch": "27"`).

### Блоки кода

```html
<script type="text/x-cpp" data-run>          <!-- полная программа, кнопка «запустить» -->
#include <iostream>
int main() { std::cout << 42; }
</script>

<script type="text/x-cpp" data-run="wrap">   <!-- фрагмент: обернётся в main + типовые #include -->
int x = 5;
std::cout << x;
</script>
```

Почему `<script>`, а не `<pre>`: внутри не нужно экранировать `<` и `&`. Код **выравнивается по левому краю** (общий отступ снимается автоматически).

| Атрибут | Значение |
|---|---|
| `data-run` | можно запустить; `="wrap"` — обернуть фрагмент в `main` (`#include` в начале фрагмента выносятся наверх) |
| `data-stdin="5 7"` | ввод по умолчанию |
| `data-ce` | пример, который **не должен** компилироваться (красная плашка) |
| `data-ub` | пример с неопределённым поведением (плашка «UB внутри») |
| `data-title="…"` | своя подпись в шапке блока |

`verify.py` компилирует и запускает все `data-run`: ошибка компиляции или зависание считаются провалом. Для `data-ce`, наоборот, компиляция **должна** упасть.

### Врезки

```html
<aside class="c c-def" data-l="Определение"><p>…</p></aside>
```

| Класс | Что это | Подпись по умолчанию |
|---|---|---|
| `c-def` | определение | Определение |
| `c-imp` | важно (жёлтый маркер) | Важно |
| `c-ub` | UB, ловушка | ⚠ UB / ловушка |
| `c-tip` | лайфхак | Лайфхак |
| `c-hist` | история | Историческая справка |
| `c-prod` | пример из индустрии | А в индустрии |
| `c-meme` | мем, разрядка | мем-пауза |

`data-l` переопределяет подпись.

### Квизы

```html
<div class="qz" data-type="single" data-ans="3">
  <div class="q">Как сбросить 3-й бит?</div>
  <ol><li>…</li><li>…</li><li>…</li><li><code>flags &amp;= ~(1 &lt;&lt; 3);</code></li></ol>
  <div class="why">Объяснение после ответа.</div>
</div>
```

| `data-type` | `data-ans` | Проверка |
|---|---|---|
| `single` | индекс верного варианта **с нуля** | выбор одного |
| `multi` | индексы через запятую: `0,1,5` | выбор нескольких |
| `text` | варианты через `\|`: `6\|шесть` | без учёта регистра и пробелов |
| `out` | ожидаемый вывод; многострочный — внутри `<pre class="ans">` (можно несколько) | сравнение вывода без хвостовых пробелов |
| `open` | — | свободный ответ: эталон в `.why`, самопроверка и проверка ИИ |

Внутрь квиза можно положить `<script type="text/x-cpp">` с кодом, он покажется над вариантами. `data-ph` задаёт placeholder поля ввода.

**Правило для `.why`:** объяснение пишется сразу верным и окончательным, без «стоп, на самом деле…».

`verify.py` запускает код из квизов типа `out` и сверяет вывод с `data-ans`/`pre.ans`. Код в таком квизе должен быть полной программой. Ответ `CE` означает «не компилируется» (это тоже проверяется), `UB` — вывод не сверяется.

### Виджеты

```html
<div class="viz-slot" data-viz="bits" data-cfg='{"type":"int16","value":32767}'></div>
```

| `data-viz` | `data-cfg` |
|---|---|
| `bits` | `type`: `int8\|uint8\|int16\|uint16\|int32\|uint32`, `value`; `ops: true` — режим битовых операций со вторым операндом `b`; `only: [...]` — ограничить типы |
| `ieee` | `value` — разбор float32 на знак, экспоненту и мантиссу |
| `align` | `fields: [["char","a"],["long","c"],["int","b"]]` — раскладка структуры (размеры LP64), переключатель `#pragma pack(1)` |
| `matrix` | `pattern`: `rows\|cols\|snake\|diag\|spiral`, `n` |

`data-cfg` — JSON в **одинарных** кавычках атрибута. `build.py` проверяет, что он парсится.

**Новый виджет:** добавь `Widgets.myviz = (el, cfg) => { const box = vizBox('Заголовок', ...контролы); …; el.replaceWith(box); }` в `widgets.js`. Используй `h()` и токены цвета.

### Трассировщик памяти

Пошаговый «отладчик»: слева код с подсвеченной строкой, справа кадры стека, куча и стрелки указателей. Шаги **пишутся руками**: это иллюстрация, а не настоящий отладчик.

```html
<div class="trace" data-title="swap через указатели">
<script type="text/x-cpp">
void swap(int* px, int* py) { … }
int main() { … }
</script>
<script type="application/json">{"steps":[
 {"l":9, "n":"Пояснение к шагу (HTML)",
  "st":[{"f":"main()", "v":[["x","int","0",{"a":"0x7f20"}], ["p","int*","0x7f20",{"p":"x"}]]}],
  "hp":[{"id":"h1","l":"new int[3]","a":"0x5a20","c":["1","2","3"]}],
  "out":"что уже напечатано"}
]}</script>
</div>
```

- `l` — номер строки (с 1), `n` — комментарий к шагу.
- `st` — кадры стека сверху вниз: `f` — подпись кадра, `v` — переменные `[имя, тип, значение, опции]`.
  - Опции: `a` — показать адрес; `p` — указывает на переменную или ячейку (`"x"`, `"a.2"` — элемент 2 массива `a`, `"h1"`, `"h1.0"`); `id` — своё имя цели для стрелок; `dead` — переменная уже не жива; `dang` — висячий указатель (красная стрелка в никуда).
  - Массив — `val` в виде JSON-массива строк.
- `hp` — блоки кучи: `id`, `l` (подпись), `a`, `c` (ячейки), `free: true` — освобождён.
- `gl` — глобальные переменные в том же формате, что `v`.
- `out` — накопленный вывод; если нет ни в одном шаге, панель вывода скрыта.

Значение, изменившееся с прошлого шага, подсвечивается автоматически.

## Задачи (`src/tasks_def.py`)

```python
task('gcd', '09', 'НОД двух чисел', 'easy', 'sem',
     '<p>Условие в HTML.</p>',
     r'''#include <iostream>
int main() { … эталон … }''',
     ['12 18', '7 13', '0 5'],              # входы тестов; выходы посчитает эталон
     inp='Два числа.', out='Их НОД.',
     starter=io_starter('#include <numeric>\n'),
     hint='Алгоритм Евклида.')
```

| Поле | Значение |
|---|---|
| `id` | уникальный, латиницей; адрес `#task-<id>` |
| `ch` | id главы |
| `lvl` | `easy` \| `medium` \| `hard` |
| `src` | `sem` (семинар), `lect` (лекция), `lc` (LeetCode-стиль) — бейдж и фильтр |
| `tests` | входы. Первые `show` (по умолчанию 2) открыты, остальные скрыты |
| `mode` | `io` — студент пишет всю программу; `func` — только функцию или класс, а `harness` (проверяющий `main`) дописывается к его коду |
| `check` | `exact` (по умолчанию, построчно без хвостовых пробелов), `tokens` (по словам), `float` (по словам, числа с допуском 1e-6) |
| `starter` | заготовка в редакторе. Для `io` есть `io_starter(extra_includes)` |
| `hint`, `solNote` | подсказка и комментарий к решению (HTML) |

Для задач с файлами есть готовый `FILE_PRE`: функция `prepare(name)` записывает stdin в файл, а harness вызывает её перед проверкой.

`gen_tasks.py` компилирует эталон с `-Wall`, гоняет его на всех входах и пишет выходы в `tasks.json`. Падение, ненулевой код возврата или ошибка компиляции дают `FAIL`, и задача не попадает в файл. Предупреждения выводятся как `WARN`: их увидит и студент, так что чини.

## Вопросы «что выведет» (`src/gen_seminars.py`)

```python
add(3, '3.4', '09', 'Что выведет программа?', '''#include <iostream>
int main() { … }''', why='Объяснение.')                         # type='out'; ответ посчитает компилятор
add(1, '1.2', '02', 'Тип литерала 42LL?', type='single', opts=['int', 'long', 'long long'], ans=2, why='…')
add(2, '2.8', '02', '…', code, ans=['4 8 8', '4 4 8'], plat=True)   # несколько верных ответов (платформа)
add(5, '5.9', '13', '…', code, ub=True, ans=['UB'])                # UB: ответ «UB», реальный вывод показывается с пометкой
```

- Аргументы по порядку: номер семинара, номер вопроса, глава, текст. Дальше `code`, `type` (`out|single|multi|text|open`) и именованные поля.
- `wrap='main'` оборачивает фрагмент в `main`, `wrap='inc'` только добавляет типовые `#include`.
- Для `out` без `ans` ответ = реальный вывод. С `ans` генератор сверяет его с реальностью и пишет `MISMATCH`, если не совпало (кроме `ub` и `plat`).
- id вопроса: `s<семинар>-<номер с дефисами>`. Он же ключ прогресса, не переименовывай.

## Флешкарты и теория

`src/gen_cards.py`:

```python
ch('05',
 ('Вопрос на лицевой стороне, можно `код` и **жирный**', 'Ответ.\nПеренос строки, ```блок кода```'),

```

id карточки `c<глава>-<номер>` — ключ прогресса Лейтнера, поэтому новые карточки добавляй в конец главы.

`src/gen_theory.py`: `q('05', 'Билетный вопрос', 'Эталонный ответ по конспекту')`. Эталон видит ИИ-экзаменатор (оценивает ответ по 30-балльной шкале) и студент после сдачи.

## Добавить главу: чек-лист

1. Создай `content/ch27.html` и добавь запись в `manifest.json`.
2. `python3 src/verify.py 27` — все `data-run` компилируются и работают, ответы `out`-квизов совпадают.
3. Задачи по главе — в `tasks_def.py`, затем `python3 src/gen_tasks.py`.
4. Карточки и теория — в `gen_cards.py` и `gen_theory.py`, затем запусти оба.
5. `python3 src/build.py` — проверит баланс тегов, JSON квизов, трейсов и `data-cfg`.
6. Открой главу в браузере на ширине ~400 px: горизонтального скролла страницы быть не должно, широкий код скроллится внутри блока.

## Стиль контента

- Язык и терминология — как в конспекте: операция (operator) и оператор (statement), lvalue/rvalue, UB, CE.
- Тон живой, мемы приветствуются, но **технически точно**. Если конспект ошибается, мягко поправь во врезке и сошлись на стандарт.
- Платформенно-зависимое (`sizeof(long)`, порядок вычисления, вывод при UB) всегда помечай.
- Объяснения пиши сразу верными: без самоисправлений вида «ой, на самом деле».

## Известные ограничения

- Нет стриминга ответов ИИ: текст появляется целиком после каждого раунда.
- Прогресс только в `localStorage`, синхронизации между устройствами нет.
- Санитайзеры недоступны на Windows/MinGW.
- Квизы в главах привязаны к порядковому номеру (см. «Прогресс» выше).
- Семинар 13 (исключения, контейнеры) не перенесён: это материал второго модуля.
